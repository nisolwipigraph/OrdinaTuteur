# OrdinaTuteur

OrdinaTuteur — помощник для Windows. Напиши, что хочешь сделать, и программа
будет предлагать по одному следующему шагу. Чтобы дать подходящую подсказку,
она делает снимок экрана и отправляет его вместе с задачей в LimitDeck AI.

Окно написано на C# и WinUI. Снимок экрана и запрос к ИИ делает Python-файл
`brain.py`. Эти две части общаются текстом в формате JSON: C# запускает Python,
передаёт ему команду и читает ответ.

## Что нужно на компьютере

Проект рассчитан на другой компьютер с Windows 11 (64-bit, x64). Подойдёт и
Windows 10, но проверялся путь именно для Windows 11.

Нужно установить:

1. **.NET 10 SDK** — чтобы собрать окно. Скачивается с сайта Microsoft.
   После установки команда `dotnet --version` должна показывать версию 10.
2. **Python 3** — чтобы делать снимок и спрашивать ИИ. Подойдёт обычный
   установщик с python.org. Команда `py -3` или `python` должна открывать
   Python 3.
3. **Pillow** — библиотека Python для снимка экрана. Её не обязательно ставить
   руками: `start.vbs` сам выполнит `pip install`, если Pillow ещё нет.
   Вручную это делается так:

   ```powershell
   py -3 -m pip install -r requirements.txt
   ```

   Если команды `py` нет, используй `python` вместо `py -3`.

Visual Studio не обязательна. Она нужна, только если хочешь открыть проект
кнопкой и собирать его из редактора. Тогда открой файл `OrdinaTuteur.sln`.
В Visual Studio должна быть поддержка .NET 10 и приложений Windows (WinUI).

Интернет нужен при первой сборке (скачиваются библиотеки окна) и при каждом
запросе к ИИ.

## Как запустить

1. Скопируй всю папку проекта на новый компьютер. Внутри не должно быть
   чужих путей: программа сама находит свои файлы рядом с собой.
2. Открой `AIKey.py` и проверь, что в переменной `API_KEY` указан твой ключ
   LimitDeck AI. Это пароль. Не публикуй файл и не отправляй его другим людям.
3. Дважды щёлкни `start.vbs`.

`start.vbs` делает три вещи:

1. Смотрит, есть ли уже собранный `OrdinaTuteur.exe`. Если файла нет или
   исходники новее готовой программы, запускает сборку:
   `dotnet build -p:Platform=x64`.
2. Проверяет, установлен ли Pillow. Если нет, ставит его из `requirements.txt`.
   Сначала пробует `py -3`, потом обычную команду `python`.
3. Запускает окно и сразу завершается. Консоль Python при работе помощника
   не показывается.

Если сборка не удалась, появится окно с текстом. Обычно это значит, что не
установлен .NET 10 SDK. Если не удалось поставить Pillow, в сообщении будет
сказано, что нужен Python 3.

Собрать вручную можно так (папка проекта должна быть текущей):

```powershell
dotnet build OrdinaTuteur.sln -p:Platform=x64
```

После сборки программа лежит здесь:

`bin\x64\Debug\net10.0-windows10.0.19041.0\win-x64\OrdinaTuteur.exe`

Рядом с exe сборка копирует `brain.py` и `AIKey.py`. Без этих двух файлов
окно откроется, но снимок и ответ ИИ не получатся.

Обычно Python запускается командой `py -3`. Если её нет, программа пробует
`python`. Если Python лежит в необычном месте, задай переменную среды
`ORDINATUTEUR_PYTHON` полным путём к `python.exe`. Например:
`C:\Python313\python.exe`.

Папки `bin` и `obj` создаются при сборке. Их можно не копировать на другой
компьютер: `bin` — это готовая программа, `obj` — временные файлы сборки.
На новом компьютере они появятся снова после `start.vbs` или `dotnet build`.
В `obj` бывают полные пути того компьютера, где собирали проект, поэтому
старую папку `obj` лучше не переносить.

## Как пользоваться

1. Введи задачу и нажми «Отправить» или клавишу Enter.
2. Твоё сообщение появится справа. Слева появится карточка «Смотрю на экран...».
3. Окно на короткое время спрячется, чтобы не попасть на снимок.
4. Python снимет экран и спросит ИИ, какое одно действие сделать следующим.
5. Когда ответ готов, карточка меняется на текст шага. Ответ приходит целиком,
   а не по одной букве.
6. Под шагом две кнопки:
   - **Дальше** — ты сделал то, что просили. Шаг запоминается, окно снова
     прячется, делается новый снимок и запрашивается следующий шаг.
   - **Кнопка со стрелкой** — «Переделать ответ». ИИ ещё раз смотрит тот же
     снимок и предыдущий совет. Новый снимок при этом не делается.
7. Если ИИ считает задачу выполненной, номер шага пропадает, остаётся короткое
   подтверждение, а кнопка «Дальше» выключается. Переделать ответ всё ещё можно.
8. Новая фраза в поле ввода начинает новую задачу. Старые карточки остаются
   на экране, но в память ИИ уже не входят.

Пока идёт запрос, поле ввода и кнопка «Отправить» заблокированы. Два запроса
одновременно программа не отправляет.

Если запрос не удался, текст ошибки не показывается:

- у первой отправки вместо ответа появляется кнопка «Повторить»;
- у кнопки «Дальше» пустая карточка убирается, и можно нажать ещё раз;
- у переделки на экране остаётся прежний текст шага.

История задачи хранится только в памяти, пока окно открыто. На диск она
не записывается. Закрыл окно — история пропала.

## Как устроен один шаг

Порядок такой:

1. C# создаёт сессию задачи: исходная фраза, список подтверждённых шагов и
   короткая переписка.
2. Окно прячется примерно на 150 миллисекунд, чтобы Windows успела его убрать.
3. C# запускает `brain.py` с командой `capture`. Python возвращает снимок
   строкой Base64.
4. Окно снова показывается.
5. C# запускает `brain.py` второй раз, уже с командой `answer`. В команде есть
   задача, подтверждённые шаги, история, снимок и, если это переделка,
   предыдущий ответ.
6. Python добавляет версию Windows и три приложения по умолчанию: браузер,
   почту и программу для PDF. Полный список установленных программ не собирается.
7. Python отправляет всё в LimitDeck и читает ответ модели `gpt-5.6-sol`.
8. Если ответ начинается с `DONE:`, задача считается законченной. Если с
   `STEP:` — это очередной шаг. Служебное слово пользователю не показывается.
   Если модели нет ни того ни другого, текст всё равно показывается как шаг.
9. C# рисует карточку и запоминает ответ в истории этой задачи.

Кнопка «Дальше» один раз дописывает в историю фразу
«Пользователь подтвердил шаг: ...». Если потом переделать уже подтверждённый
шаг, в списке выполненных шагов меняется текст этого шага, а не добавляется
новый.

Переделка дописывает в историю просьбу проверить внимательнее и новый ответ.
ИИ при этом получает тот же снимок, что и для исходного шага.

## Как C# и Python передают данные

Python читает одну команду из стандартного ввода и печатает ответ в
стандартный вывод. Одна строка — один JSON-объект. Кодировка UTF-8, чтобы
русский текст не ломался.

Команда «сделай снимок»:

```json
{"action": "capture"}
```

Ответ:

```json
{"type": "capture", "image": "data:image/jpeg;base64,..."}
```

Команда «дай шаг»:

```json
{
  "action": "answer",
  "question": "текст задачи",
  "completed_steps": ["уже сделанный шаг"],
  "history": [{"role": "assistant", "content": "прошлый совет"}],
  "image": "data:image/jpeg;base64,...",
  "previous_answer": null
}
```

`previous_answer` равен `null`, если это новый шаг. При переделке там лежит
текст совета, который пользователь хочет проверить ещё раз.

Ответ:

```json
{"type": "result", "done": false, "instruction": "что сделать"}
```

`done: true` означает, что задача выполнена.

Если Python завершился с ошибкой или не прислал нужную строку, C# считает
запрос неудачным и показывает кнопку повтора либо возвращает старый текст.
Текст исключения пользователю не выводится.

Снимок уменьшается до 800×500 пикселей и сохраняется как JPEG, чтобы запрос
был меньше. Картинка не записывается во временный файл: она живёт в памяти
и сразу превращается в текст.

Запрос к LimitDeck ждёт не дольше 90 секунд. Длина ответа ограничена
96 токенами: ИИ должен сказать одно короткое действие, а не инструкцию на
страницу.

## Какие файлы за что отвечают

- `OrdinaTuteur.sln` — файл решения. Его открывают в Visual Studio.
- `OrdinaTuteur.csproj` — настройки сборки C#: .NET 10, WinUI, Windows x64
  и список библиотек.
- `App.xaml` — общие ресурсы окна. Подключает обычные стили WinUI.
- `App.xaml.cs` — точка входа: создаёт и показывает главное окно.
- `MainWindow.xaml` — внешний вид: чат сверху, поле ввода и кнопка снизу.
- `MainWindow.xaml.cs` — поведение окна: кнопки, история задачи, снимок и
  запуск Python.
- `brain.py` — снимок экрана, сведения о Windows, запрос к ИИ.
- `AIKey.py` — секретный ключ доступа. Не добавляй его в публичный репозиторий.
- `requirements.txt` — библиотеки Python. Сейчас там только Pillow.
- `app.manifest` — говорит Windows, что программа рассчитана на современные
  версии системы и умеет разный масштаб на разных мониторах.
- `start.vbs` — сборка при необходимости, установка Pillow и запуск.
- `README.md` — эта инструкция.

## Простые объяснения слов

- **C#** рисует окно и реагирует на кнопки. **Python** снимает экран и говорит
  с ИИ.
- **XAML** — текстовое описание того, как расположены элементы окна.
- **WinUI** — библиотека Microsoft для окон Windows 10 и 11.
- **JSON** — текст с полями и значениями. Например, поле `question` хранит
  задачу, а поле `image` — снимок.
- **История** — список прошлых реплик текущей задачи. Она живёт только в
  памяти открытого окна.
- **Сессия** — одна задача от первой фразы до закрытия окна или до нового
  сообщения в поле ввода.
- **`async` и `await`** позволяют ждать Python и ИИ, не замораживая окно.
- **Base64** — способ записать байты картинки обычными буквами, чтобы положить
  снимок внутрь JSON.
- **Реестр Windows** — системное хранилище настроек. Программа читает оттуда
  только выбранные приложения по умолчанию для браузера, почты и PDF.
- **Стандартный ввод и вывод** — «труба» текста между двумя программами.
  C# пишет команду в ввод Python и читает ответ из его вывода.

## Данные и приватность

В LimitDeck AI уходят:

- текст задачи;
- снимок экрана, сделанный перед новым шагом;
- история текущей задачи;
- короткие сведения о Windows и трёх приложениях по умолчанию.

Переделка ответа использует снимок этого же шага, а не новый. Не отправляй
экран, на котором видны пароли, письма, документы или другие личные данные.

Ключ доступа лежит в `AIKey.py`. Считай его паролем: не публикуй и не
пересылай. История задач на диск не сохраняется.
